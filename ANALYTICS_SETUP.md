# Статистика и вход в админку AMANTER

В проекте добавлены Vercel Functions (`/api/analytics`, `/api/admin/login`) и сбор анонимной first-party статистики. Для общей статистики посетителей нужен Upstash Redis REST: сайт статический, а `localStorage` из старой панели хранит данные только в браузере одного человека.

## Однократная настройка

1. В Vercel откройте проект AMANTER → **Settings → Integrations** и подключите Upstash Redis (или создайте базу Upstash Redis отдельно). Скопируйте REST URL и REST token.
2. Откройте **Settings → Environment Variables** и задайте переменные для Production (Preview — по желанию):
   - `UPSTASH_REDIS_REST_URL` — REST URL базы;
   - `UPSTASH_REDIS_REST_TOKEN` — REST token;
   - `ADMIN_PASSWORD` — новый случайный пароль не короче 16 символов;
   - `ADMIN_AUTH_SECRET` — случайный секрет HMAC не короче 32 байт.
3. Сохраните переменные и запустите **Redeploy** последнего production deployment. API-функции не начнут работать, пока переменные не добавлены.
4. Откройте `/admin`, войдите с тем значением, которое вы указали в `ADMIN_PASSWORD`, затем выберите вкладку «Статистика».

Для генерации двух секретов в терминале можно использовать:

```sh
openssl rand -base64 32
openssl rand -hex 32
```

Первое значение задайте как `ADMIN_PASSWORD`, второе — как `ADMIN_AUTH_SECRET`. Не публикуйте их в GitHub и не вставляйте в `admin.js`. Текущий пароль, который раньше был прописан в браузерном JavaScript, следует считать скомпрометированным и не использовать повторно.

## Что учитывается

- новые сеансы и просмотры страниц;
- клики по ссылкам, кнопкам и элементам меню, отдельно WhatsApp/телефон/Telegram/Instagram;
- просмотримые разделы и глубина прокрутки 25/50/75/100%;
- реферер только в виде домена, отдельно UTM-источник/канал/кампания, устройства, популярные разделы и последние события;
- периоды 24 часа, 7, 30 и 90 дней, выгрузка агрегатов в CSV.

События аналитики не содержат IP-адресов, полных URL с query-параметрами, рекламных идентификаторов или cookies. Для ограничения перебора пароля (15 минут) и частоты сбора аналитики (300 событий в минуту с временным счётчиком на 2 минуты) используются краткоживущие HMAC-ключи на основе адреса запроса; сами IP-адреса в хранилище не записываются. Идентификатор сеанса случайный и хранится только в `sessionStorage`. События удаляются по сроку хранения 90 дней; индекс также автоматически истекает после 90 дней без новых записей, и в любом случае хранится не более 20 000 последних событий. При достижении лимита более ранние события удаляются. В интерфейсе единица посещения называется «сеанс», а не «уникальный человек».

## Локальная проверка

При локальном запуске сайта задайте эти же переменные в `.env.local` или окружении Node/Vercel. `.env.example` содержит только шаблон, реальные значения не добавляйте в репозиторий.
